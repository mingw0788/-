# Task
请审查以下代码文件，识别问题并按照优先级输出。
审查维度优先级（从高到低）：安全 > 逻辑 > 性能 > 规范。

- 安全：SQL 注入、XSS、敏感信息硬编码、已知 CVE 漏洞、不安全的反序列化、路径穿越。
- 逻辑：空指针、并发竞态、边界条件遗漏、死循环、异常吞噬、off-by-one。
- 性能：N+1 查询、循环嵌套过深、不必要的对象创建、重复计算、低效的数据结构选择。
- 规范：命名规范、函数过长、重复代码、注释缺失、与团队编码规范的偏离。

# 严格要求
1. **不要输出任何行号**。行号由后续的定位层通过代码锚点确定性推导，你给出的行号会被忽略。
2. `code_anchor` 必须是**从下方代码中逐字复制**的片段，不要改写、不要补全、不要加省略号。
   锚点是定位层唯一的依据，改写会导致定位失败并被标记为 `unresolved`。
3. 单个锚点控制在 1-5 行，足以唯一定位该问题即可。过长会降低匹配精度。
4. 只报真实存在的问题。不要为了凑数而报告不存在的问题，也不要重复报告同一处代码。
5. 若代码确实没有问题，返回空的 `issues` 数组。

# 输出格式
必须严格输出以下 JSON，不要包含任何 Markdown 代码块标记：

{
  "issues": [
    {
      "issue_id": "生成唯一UUID",
      "category": "Security | Logic | Performance | Style",
      "priority": "P0 | P1 | P2 | P3",
      "severity": "Blocker | Critical | Major | Minor",
      "code_anchor": "从代码中逐字复制的片段",
      "description": "对问题的详细描述，说明为什么这是问题以及被利用或触发的条件",
      "suggestion": "具体的修改思路，不要写完整代码"
    }
  ]
}

优先级判定标准：
- P0：可被直接利用的安全漏洞，或必然导致数据损坏/服务不可用的缺陷。
- P1：严重逻辑错误、明确的性能瓶颈、高危规范偏离。
- P2：一般逻辑问题、可优化的性能点。
- P3：风格与规范问题。
